# 技术选型工作流质量优化报告（v3）

## 目标与边界

本轮只修复技术选型节点内部的质量问题，不调整 LangGraph 拓扑，不改变节点名称、节点数量、边、条件路由、入口、出口和执行顺序，也不改变 `query_router_graph.invoke({"query": ...})` 的调用方式。

保留现有七个固定指标：`performance`、`power`、`thermal`、`cost`、`maturity`、`risk`、`scalability`。新增最多三个、仅由用户明确提出的场景指标。普通 RAG、数据库内容、Embedding 模型、Milvus 集合、Neo4j 图数据和缓存策略均不在本轮修改范围内。

## 两次真实测试基线

### 测试一：数据库服务未启动

- 完整执行约 61.63 秒。
- Milvus 与 Neo4j 均连接失败，并各重试两次；最终只得到 4 条较弱的 Web 证据。
- 工作流返回 `needs_human_review`，没有足够本地证据支撑可靠选型。
- 结论：失败降级路径基本安全，但重复连接等待和弱 Web 证据不能改善选型质量。本轮不通过降低证据门槛来换速度。

### 测试二：数据库服务已启动

- Milvus 和 Neo4j 健康检查均返回 4 条结果。
- 同一个明确的 ALD/CVD 请求首次经公开入口执行时，需求模型返回空字段，约 4.35 秒后错误进入 `awaiting_user`。
- 补充澄清答案后，完整流程约 39.1 秒完成，共两轮检索、9 条证据，审核结果为 `pass`。
- 质量问题：均匀性/共形性被混入 `performance`；缺少直接证据的功耗、成本仍产生数值分；`thermal` 评分为空但没有形成缺口；综合分为空、结构化推荐对象为空，推荐文字却明确偏向 ALD；向量和图谱中的同一底层文档形成两条决策证据。

## 根因

1. 需求解析完全依赖一次模型 JSON，明确文本没有确定性补救；技术选型模型温度未独立固定为 0。
2. 固定指标无法承载“薄膜均匀性与共形性”等场景关键指标，导致语义错位。
3. 证据只有粗粒度的候选和指标标签，没有“候选 × 指标 × 直接性 × 原文片段”的可验证关系。
4. 评分只校验证据 ID 是否存在，没有验证引用是否直接支持该候选和指标。
5. 推荐和审核过度依赖模型自洽，缺少综合分、首选对象、推荐文字之间的确定性一致性门。
6. 去重指纹优先使用检索侧 ID，无法识别向量与图谱对同一文档的包装副本。

## 架构决策

### ADR-1：场景指标是固定指标的增量，不替代固定指标

`SelectionRequirements` 增加可选 `scenario_criteria`，最多三个，优先级为 `highest/high/medium/low`。生产效率仍属于 `performance`；均匀性与共形性作为独立场景指标展示和评分。

### ADR-2：只有可核验的直接证据才能产生数值评分

每条证据增加逐项支持关系，包括候选 ID、指标 ID、`direct/indirect/none` 和原文片段。只有原文片段能够在证据正文中核验、且 Web 证据具有 URL 时，关系才可保留为 `direct`。旧字段 `candidate_ids` 和 `criteria` 继续保留，但只从有效直接支持关系派生。

### ADR-3：推荐由确定性质量门约束

- 七个正权重固定指标全部具有直接证据且排名明确，才允许 `recommend`。
- 最高优先级场景指标具有直接证据、但固定指标仍不完整时，可输出 `conditional`，同时必须给出结构化首选候选 ID 和场景决策依据。
- 没有可审计首选候选时，只能输出 `insufficient_evidence`，且不得通过文字暗示某候选更优。

### ADR-4：保持两证据包、最多两轮和原有图结构

本轮不增加节点或模型轮次。需求恢复、证据校验、去重、评分校验和审核否决均在现有节点内部完成。

## 实施范围

- 确定性技术选型模型配置与需求字段恢复。
- 场景指标的数据模型、提示词、检索、评分、缺口和报告链路。
- 逐项证据支持关系、Web 来源校验、跨向量/图谱副本去重。
- 固定指标完整性、条件推荐、首选候选和审核结果的一致性硬规则。
- 面向以上行为的单元测试、结构回归、普通 RAG 回归和真实 ALD/CVD 验收。

## 验收标准

- 明确的 ALD/CVD 请求一次识别业务目标、应用场景、候选和最高优先级场景指标，不进入无意义澄清。
- 只有有效直接证据可产生分数；缺失直接证据的功耗、成本、成熟度等保持空分并形成相同缺口。
- 同一底层文档的向量和图谱副本只形成一条决策证据，同时保留两个检索来源。
- 综合分、结构化首选、推荐文字和审核结果一致；无可审计首选时不暗示 ALD 或 CVD 更优。
- 节点、边、入口、出口、条件路由、执行顺序与公开调用接口保持不变。
- 不联网的单元测试、逐文件回归、编译和主图导入全部通过。
- 数据库正常且完成预热后，真实 ALD/CVD 完整执行不超过 90 秒；相同请求短时缓存命中不改变报告。

## 验收记录

实施前基线见“测试一”和“测试二”。本轮实施后结果如下：

- 技术选型 JSON 模型已固定为温度 0 并关闭思考；普通 RAG 模型配置未变。
- 明确 ALD/CVD 原句即使遇到模型空字段，也可恢复业务目标、应用场景、候选方案和最高优先级“薄膜均匀性与共形性”，不再进入无意义澄清。
- 场景指标具有稳定 ID，并进入首轮检索、直接证据归属、补检缺口、评分、推荐和报告全链路。
- 证据必须同时通过候选、指标、直接性、原文片段、指标语义和 Web URL 校验；共形性证据不能再单独生成 `performance` 分数。
- 向量与图谱对同一来源正文的包装副本合并为一条决策证据，同时保留 `retrieval_sources`。
- 综合分、条件性首选、推荐文字和审核结论增加确定性一致性门；报告已拆分“场景关键指标”和“固定指标”，空综合分显示为“未计算”并列出缺失指标，推断风险显式标记。

真实 ALD/CVD 公开入口验收：

- 预热结果：Milvus `ready`，Neo4j `ready`。
- 首次完整执行 61.63 秒，低于 90 秒目标；相同请求缓存复跑 0.03 秒，报告完全一致。
- 得到 8 条去重证据，检索来源包含 vector、graph、local_hybrid 和 web_search。
- 需求一次识别 ALD、CVD 和最高优先级场景指标；未进入澄清。
- ALD 的场景指标基于直接证据评分为 5；缺少直接证据的固定指标保持空分，综合分不计算。
- 最终结论为 `conditional`，结构化首选为 `ald`，决策依据为 `scenario_criteria`，审核结果为 `pass`；CVD 和固定指标缺口仍保留在待验证项中。

自动化验收：

- 15 个测试文件均按独立 Python 进程运行，共 171 项测试全部通过。
- `python -m compileall -q src tests` 通过。
- `query_router_graph` 与 `technology_selection_graph` 均可导入为 `CompiledStateGraph`。
- 技术选型图仍为 14 个含起止节点；结构回归确认节点、边、条件路由和顺序未变。
- 普通 RAG 的 `MAX_TRANSFORM_COUNT` 仍为 2。
